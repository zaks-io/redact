# Agent workflow test contracts

Status: synthetic inputs and independent expected results consumed by
[real executable integration tests](workflows.rs). All named cases run with
cleared child environments in normal validation and release workflow checks.
No fixture is ignored or skipped when a binary is absent.

```sh
cargo test --locked --test workflows -- --test-threads=2 --nocapture
cargo test --locked --release --test workflows -- --test-threads=2 --nocapture
```

## Fixture format

`fixture_version` is `1`; `synthetic_only` must be true. Each case contains:

- `id`: stable test identifier, used in the acceptance mapping.
- `binary`: `rprintenv` or `rstr`.
- `args`: exact argv entries, passed directly without a shell.
- `environment`: complete synthetic application environment.
- `files`: relative temporary file paths mapped to their UTF-8 contents.
- `stdin_utf8`: complete input, followed by EOF, without an extra newline.
- `expect`: exit code, stdout assertions, and stderr assertions.
- `hidden_canaries`: synthetic values that must not occur in stdout or stderr.

Require exactly one stdout expectation: byte-exact `stdout_utf8` or structurally
exact `stdout_json`. JSON object key order and insignificant whitespace are
irrelevant; array order, nulls, fields, and values must match. Extra records and
fields fail. For stderr, require either byte-exact `stderr_utf8` or all listed
`stderr_contains` fragments. Additional error text must still satisfy the safe
error contract. All success cases require empty stderr.

The fixtures intentionally include a bare value `rstr` cannot recognize. Its
presence in output is expected and does not belong in `hidden_canaries`. Never
relax a recognized-secret assertion to make an implementation pass.

## Runner requirements

Use the real Cargo-built binaries via integration tests. For each case, create
a fresh temporary directory, populate its synthetic files, clear the child
environment, set only the fixture environment, set the working directory, pipe
stdin, close it, and capture both output streams and status. Never mutate the
test runner's global environment. Do not invoke a shell for ordinary cases.

Do not discover real `.env` files or inherit real application credentials.
Any OS-required child-process setup must be explicit and must not import values
from the developer's environment. Reject unknown fixture fields, duplicate IDs,
unsafe fixture paths, and unsupported versions rather than skipping cases.

Run every case as a named test or named subcase on Linux and macOS. Report which
case failed. Use a bounded subprocess timeout and terminate the synthetic child
on timeout rather than hanging CI. A missing executable is a failure, not a skip.

Replay `stable_text_fingerprint` in separate processes and compare exact output.
Pair the malformed and corrected cases for each tool into recovery scenarios.
The corrected input is generated by the harness from synthetic fixtures; an
agent does not need to view the failing raw input to understand the diagnosis.

The fixtures contain literal expected hashes. Production fingerprint functions
must never generate expected output during tests. Validate them independently
when editing fixtures. Equivalent hashes across tools are intentional.

## Additional integration coverage

Some requirements need more than one plain subprocess fixture:

- Actual producer stdout/stderr piped into `rstr` without upstream capture in an
  agent transcript; capture only the downstream result.
- Interactive-terminal input rejection using a pseudo-terminal.
- Debug/display/nested-error formatting and detector-initialization failure.
- I/O failures, input-size boundaries, and chunk boundaries.
- Help content explaining presence versus readiness, context-preserving piping,
  stable fingerprints, and safe recovery.

These cases are mandatory in [the usability spec](../docs/agent-usability.md).
The fixture corpus is a starting set, not a substitute for the full acceptance
and fuzzing requirements.
