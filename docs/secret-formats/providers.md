# Provider token formats

See [evidence definitions](README.md#evidence-vocabulary). Checked 2026-10-04.
Prefixes below are public format markers, never copied complete credentials.
Unless explicitly stated, the cited source does not establish a universal body
length or alphabet. Do not manufacture one from an example.

## Source control and package registries

| github-checksummed-legacy | 2021 documented version: prefix plus 30 Base62 random characters and six Base62 checksum characters encoding CRC32 | Historical format evidence; not a universal grammar for fine-grained PATs or current installation tokens. | gitlab-other | Documented `gloas-` OAuth app secret, `gldt-` deploy, `glrt-`/`glrtr-` runner auth, `glcbt-` CI job, `glptt-` trigger, `glft-` feed, `glimt-` incoming mail, `glagent-` agent, `glwt-` workspace, `glsoat-` SCIM, `glffct-` feature-flag client | Version-dependent; custom instance prefixes can be prepended to multiple families. `_gitlab_session` is cookie context, not the token's own prefix. | azure-devops-pat | Documented 84-character PATs including 52 randomized characters and an `AZDO` signature | Documentation describes the four-letter signature at positions 76 through 80, an ambiguous five-position range. | npm-token | Documented `npm_` format announcement; final six Base62 characters encode CRC32. | pypi-token | Documented `pypi-`; used as the password with username `__token__` | No fixed length established. `__token__` is a username marker, not the secret. | [PyPI token help](https://pypi.org/help/#apitoken) |
| huggingface-token | Example-backed `hf_` in official user-token documentation | Do not infer read/write/fine-grained scope or a fixed total length from the prefix. | [User access tokens](https://huggingface.co/docs/hub/en/security-tokens) |
| docker-token | Context-only personal access token used instead of a password | No normative `dckr_pat_` body grammar was verified in this pass.
